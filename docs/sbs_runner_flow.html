01Global setup

Resolved once, before any stage runs.

KeyDefaultEffect
SWATrueFalse skips scan-wise activation and requires an existing dict_ref_with_activation.pkl — for re-running downstream stages without resolving raw data again.
USE_IMSTrueOnly supported value; False raises NotImplementedError (mzML/non-IMS path was never finished).
N_CPU-1<0 pulls SLURM_CPUS_PER_TASK (falls back to 1 outside Slurm). Also seeds OPTIMIZATION.N_BATCH when that is left at -1.
ADD_TIMESTAMP_TO_RESULT_PATHFalseTrue appends a run timestamp to RESULT_PATH, then flips itself back to False in the in-memory config so a reused config file doesn't double-stamp.
EXCLUDE_DATASET_NAME[]Raw file basenames dropped from both dictionary construction and the SWA .d file loop.

02Prepare Dictionary

Skipped wholesale if RESULT_PATH/dict_ref.pkl already exists.

KeyDefaultEffect
PREPARE_DICT.SEARCH_ENGINEmaxquantOne of maxquant / sage / fragpipe; selects the evidence file format and parser (sage_parser, fragpipe_psm_parser).
PREPARE_DICT.OK.DIR"" (disabled)Non-empty path filters evidence by Oktoberfest rescoring output at PREPARE_DICT.OK.FDR, output type per PREPARE_DICT.OK.OUTPUT (psms/peptides).
PREPARE_DICT.MERGE_CONFOUNDERS.ENABLEDFalseTurns on coSWA: co-eluting isobaric candidates get merged into one confounder group, later solved jointly in SWA and quantified with per-member role/anchor snapping in match_features.
PREPARE_DICT.RT_REF / IM_REFpred / refReference RT from a PeptDeep prediction; reference IM taken directly from search-engine output.

03Scan-Wise Activation

Runs once per .d file when SWA is True; the coSWA group-window indexing step only fires if dict_ref already carries GroupIM_search_left (i.e. MERGE_CONFOUNDERS ran upstream in dictionary construction).

KeyDefaultEffect
OPTIMIZATION.N_BATCH-1 (= N_CPU)Number of round-robin batches of MS1 scan indices handed to process_frames_parallel.
OPTIMIZATION.DELTA_MOBILITY_INDEX_THRES80Currently inert — only read when extract_im_peak=True, which the runner hardcodes to False.
OPTIMIZATION.IM_PEAK_EXTRACTION_WIDTH4Currently inert — same extract_im_peak=False hardcode as above.
PREPARE_DICT.MERGE_CONFOUNDERS.ENABLEDFalsePassed through as merge_confounders to process_frames_parallel — confounder-group members are sparse-coded jointly rather than independently.

04Feature-Feature Match & Quant

The largest stage. broad_alignment's two shift tables (peptide-calibration and image-based) and the mz-sorted activation parquets are all build-once-reuse caches, independent of any config re-check beyond "does the file exist". The image-based table additionally reopens every raw .d file via AlphaTims (parallelized, disk-cached per raw file) -- the peptide-based table only needs dict_ref/Stage-2 activation output.

KeyDefaultEffect
MATCH_FEATURES_KWARGS.align_imagesTrueFalse skips alignment entirely; rt/im shift and template_matching_score become fixed 0.0 sentinels downstream.
MATCH_FEATURES_KWARGS.alignment_methodtemplate_match"template_match" (default): sliding-window match_template search of a template_frac-sized reference crop within each run's (possibly larger) search image. "phase_correlation": skimage.registration.phase_cross_correlation between the FULL resized reference and each run's full resized image (FFT-based, sub-pixel accurate to 1/phase_correlation_kwargs.upsample_factor, rounded to the nearest pixel) finds the shift -- the global search is needed to find the signal, phase correlation can't crop first -- but the registration error is then recomputed on the same anchor-centred, template_frac-sized crop template_match uses (after applying the discovered shift), not the full image, so background pixels elsewhere in the patch don't dilute it; template_frac stays meaningful under both methods, just for a different purpose each time. Same template_matching_score column either way, but the sense flips: match_template's [0, 1] score (higher = better) vs. phase_cross_correlation's windowed registration error (lower = better, unbounded) -- anything reading the column downstream must know which method produced a given run's rows. Requires use_shift_crop_pad=False and is incompatible with broad_alignment.enabled/multi_scale_template_fracs (no windowed-search or correlation-surface concept for phase correlation) -- either combination raises a config error before any batch is processed.
MATCH_FEATURES_KWARGS.phase_correlation_kwargs.upsample_factor10Sub-pixel registration precision (1/upsample_factor pixels) passed to phase_cross_correlation. Only used when alignment_method="phase_correlation".
MATCH_FEATURES_KWARGS.phase_correlation_kwargs.normalizationNoneNone (raw cross-correlation) or "phase" (phase-only whitening), passed to phase_cross_correlation. None matches the convention already used for full-image phase correlation elsewhere (swaps.postprocessing.rt_im_image_registration) -- phase-only whitening is noise-sensitive on this sparse data. Only used when alignment_method="phase_correlation".
MATCH_FEATURES_KWARGS.template_match_top_intensity_frac1.0Restricts the template-matching correlation search to only the top n pixels by intensity in each search image/template, where n = this fraction × the reference image's pixel count -- a fixed pixel budget derived once from the reference's own size and applied uniformly to the template and every run's search image (regardless of each image's own size), zeroing everything else. E.g. 0.05 on a 200×50-pixel reference keeps only the strongest 500 pixels per search image. Search-space-only, same scope as align_in_log_space: applied after that transform (rank order is preserved, so the same pixels are kept regardless), and the returned aligned/consensus images stay unfiltered. Recorded on the alignment state so peptide-swap decoys (main and every multi_scale_template_fracs scale) and visualize_dir diagnostic plots apply/show the same filter. Must be in (0, 1]; 1.0 (default) = no filtering. Under alignment_method="phase_correlation" this also gates the windowed registration-error crop: a reference_mask (top-n-by-intensity pixels within just that crop, n resolved from the crop's own size) is derived from the reference and applied to both crops before recomputing the error, so background pixels inside the anchor-centred window don't count toward it either.
MATCH_FEATURES_KWARGS.broad_alignment.enabledFalseCenters each candidate's per-run search on a precalibrated shift instead of searching the whole image. Auto-builds two tables once per RESULT_PATH (both build-once-reuse caches, shared across quantification_* variants): broad_alignment_shift_table.parquet (peptide-calibration + template match, RT-binned in minutes, swaps.postprocessing.broad_alignment) and broad_alignment_shift_table_global_raw_image.parquet (full-image phase correlation between every raw-file pair, per-pair param sweep, keyed by MS1 frame index, swaps.postprocessing.broad_alignment_image_based) -- match_features.py's ShiftLookup actually consumes only the second (image-based) table; the peptide-based table is still generated but no longer read. No-ops with a warning if align_images=False.
MATCH_FEATURES_KWARGS.broad_alignment.max_deviation5Search radius (pixels) around the calibrated shift; 0 forces the exact calibrated shift and unlocks the delta_* FDR features (see Stage 4 below).
MATCH_FEATURES_KWARGS.broad_alignment.multi_scale_template_fracs[]Extra template_frac values to additionally search at (e.g. [0.1, 0.3, 0.45]), alongside the main MATCH_FEATURES_KWARGS.template_frac -- adds shift_rt/shift_im/template_matching_score/delta_* columns suffixed _frac_<x> per value, for real targets and both decoy strategies (peptide-swap decoys get a genuine re-search per scale; off-target decoys and the consensus row reuse/sentinel the main scale's values). Only takes effect under the same gate as delta_* above (broad_alignment.enabled AND max_deviation == 0); empty list (default) = zero extra cost.
MATCH_FEATURES_KWARGS.broad_alignment.image_based.window_widths[40, 60, 120, 240]Sliding-window widths (MS1 frames) swept per raw-file pair when fitting the image-based rt_shift(rt) curve in calibrate_broad_alignment_image_based. Every pair also always considers a plain whole-image global shift as a candidate -- whichever candidate (global, or one window_width/stride/method combo) has the lowest L1 registration residual wins for that pair.
MATCH_FEATURES_KWARGS.broad_alignment.image_based.strides[5, 20]Sliding-window strides (MS1 frames) swept alongside window_widths -- together with it, up to 4x2=8 piecewise candidates + 1 global candidate are compared per raw-file pair.
FDR.ENABLEDTrueFalse skips decoy generation entirely in match_features_batches_parallel (decoys only exist to feed percolator).
MATCH_FEATURES_KWARGS.dir_namequantificationOutput subdirectory name under RESULT_PATH; gets a _no_fdr suffix automatically whenever FDR.ENABLED=False, so the two output modes never collide.
MATCH_FEATURES_KWARGS.consensus_decoy_kwargs.strategies[peptide_swap]Decoy construction strategy list; off_target_shift is the alternative/additional strategy.

05FDR Control

Percolator is always trained and scored on the full target+decoy pool regardless of ONLY_SCORE_MATCH — that flag only gates which rows are exempted from the resulting q-value filter (recent fix, see commit 746a90d).

KeyDefaultEffect
FDR.INT_THRES100Intensity floor applied first, uniformly, to every pp row (target/decoy, Match/MS-MS alike) before any other gate; 0 disables it.
FDR.ONLY_SCORE_MATCHTrueTrue routes Reference/Quant-Only ("MS/MS-status") rows straight to output labeled "MS/MS", skipping the q-value<0.01 filter; only "Match"-status rows are held to it.
FDR.ENABLEDTrueFalse skips Mokapot/percolator entirely — pp_match_target_filtered is just the intensity-filtered pool, written to intensity_filtered_postprocessing/ instead of a percolator_postprocessing_*/ dir.
FDR.PERCOLATOR_POST_PROCESSINGtdctdc (target-decoy competition, percolator -Y) or mix-max (percolator -y); also names the output subdirectory.
FDR.TRAIN / FDR.TEST0.01 / 0.01Passed to percolator as -F/-f. FDR.TRAIN also suffixes the output subdirectory (percolator_postprocessing_<method>_trainfdr<value>/) since it changes what percolator learns, unlike ONLY_SCORE_MATCH. Default matches percolator's own built-in -F default (0.01), which is what every run used before these were wired up.
MATCH_FEATURES_KWARGS.align_imagesTrueGates whether alignment-derived columns (rt/im shift, template_matching_score) enter the percolator feature set at all, vs. base geometry/correlation features only.

06DirectLFQ + Result Analysis

Runs unconditionally once FDR control produces pp_match_target_filtered; the only branch is whether a coSWA undistinguishable-ion exclusion file exists to warrant a second DirectLFQ pass, and whether an IonQuant combined_ion.tsv is present for comparison plots.
